# Frozen replay data package

Status: published research checkpoint, 2026-10-22. The repository contains a
curated, compressed copy of generated replay inputs and outputs in
[`data/replay-studies`](../data/replay-studies/README.md). The original, ignored
`results/` directory is retained locally; its approximately 29 GB are not added
to Git.

## Origin and interpretation

All road-user data in this package are synthetic. Three moving recordings were
generated by the existing C++ Simulator, with requested initial populations of
200, 500 and 1,000 road users. Each recording covers 20 seconds, an 80 × 80 m
area and the seven configured simulation profiles. Frozen observations preserve
100 ms sensor acquisitions and simulated positions/identities. They are not
real-person records or a new claim of urban motion realism.

The local-policy input is a separate scripted mechanism fixture: 20 stable
synthetic identities and 380 observations. It isolates policy effects on a few
leaves; it is not a moving shopping-street scenario.

Synthetic tracking identities are deliberately preserved to audit distinct
support and the relationship between source and released counts. This makes
the package identity-bearing research data. Publishing it does not demonstrate
a formal anonymity or privacy guarantee.

## Scope

The package includes:

- Three moving observation files, each stored once.
- 15 matched moving comparison contexts: 153 results and 15 deterministic
  repeat outputs, plus policies, audits, summaries and original manifests.
- Eight semantic-release results and two repeat outputs, using the same frozen
  500-user recording.
- Four local-policy results and one repeat, with the scripted input, policies,
  scalar/semantic audits and execution provenance.
- Frozen Python evaluation sources, protocols and selected verification
  records where they were archived by the original studies.
- 17 usable viewer bundles after restoration.

Six deterministic tar/gzip archives contain 702 original files and total
**47,073,268 compressed bytes** (44.89 MiB). Their members occupy
1,761,468,021 bytes before canonical inputs are copied into each restored
comparison bundle. Allow approximately 2 GB for restoration. The complete
inventory, source-relative paths, file hashes, archive hashes and byte counts
are in [`manifest.json`](../data/replay-studies/manifest.json).

Compiled binaries, build trees, raw MongoDB GT/AGBS exports, duplicate moving
inputs, verbose per-query occupancy dumps, external paper PDFs, extracted paper
text and rendered paper pages are excluded. Original capture proofs preserve
the recorded GT/AGBS consistency checks. The raw exports needed to independently
repeat those particular checks are not included.

## Verify without restoring

From the repository root, with Python 3.10 or later:

```sh
python3 -B tools/evaluation/replay_data.py verify
```

This streams every member, checks its exact byte count and SHA-256, validates
the archive inventory, and checks each compressed archive's SHA-256. A hash
match establishes agreement with this repository manifest; it does not turn
the manifest into an independent proof of origin.

## Restore and inspect

Choose a new output directory. The tool refuses to replace an existing target
and rejects archive traversal, links, duplicate/unlisted members and symlink
ancestors. It never executes a command from archived historical metadata.

```sh
mkdir -p results
python3 -B tools/evaluation/replay_data.py restore --output results/replay-data
python3 -B tools/replay_viewer/serve.py --bundle results/replay-data/local-policies --port 8770
```

Open `http://127.0.0.1:8770/`. Other restored bundle directories include:

```text
moving-pilot/n500/comparison
cell-caps/cap5/n500/comparison
four-second/window4000/cap5/n500/comparison
semantic-release
local-policies
```

The restore manifest lists every available bundle. Canonical observations are
copied byte-for-byte into comparison directories so the original viewer bundles
remain usable without editing their manifests. No MongoDB server, simulator
window, network download or JavaScript build is required for inspection.

For a fresh algorithm replay, build the current replay executable and explicitly
select a policy and matching parameters:

```sh
cmake -S simulator -B simulator/build
cmake --build simulator/build --target AggregationReplay -j 4
./simulator/build/AggregationReplay --help
```

Consult each study's frozen policy/protocol and current tool usage. Historical
outputs remain byte-exact evidence. Current defaults, source revisions and
compiler dependencies may differ from the historical executable; an identical
rebuild is not asserted. Original motion generation was stochastic and cannot
be regenerated exactly from a seed. Replaying the frozen observations avoids
that problem when comparing aggregation choices.

## Provenance and assembly

Every selected file retains its original bytes and hash. Historical manifests
may mention excluded files, local absolute paths, dropped capture databases or
old executable locations. Those fields are preserved as evidence; they are
not portable instructions and are not used by restoration. Database owner
tokens belonged to already dropped, isolated synthetic capture databases and
are not access credentials.

`data/replay-studies/assemble.py` records the exact curation recipe. Reassembly
requires the original ignored results, including the local-policy study, and
an empty output directory:

```sh
python3 -B data/replay-studies/assemble.py --output /private/tmp/ump-replay-package-new
```

Tar member order, metadata and gzip timestamp are deterministic. The verifier
and restore helper use only Python's standard library. Five focused tests cover
deterministic byte-preserving restoration, corruption and digest failure,
existing destinations, symlink ancestors, traversal and duplicate/unlisted/
missing archive members:

```sh
python3 -B -m unittest discover -s tools/evaluation -p test_replay_data.py
```
